# Работа с проектом

Начните с [README](README.md): там описаны продукты, архитектура и локальный запуск. Для заметного изменения откройте Issue с задачей и ожидаемым поведением. Ошибки безопасности передавайте по [SECURITY.md](SECURITY.md).

## Подготовить изменение

1. Создайте отдельную ветку от `master`.
2. Добавьте воспроизводимый тест к исправлению. Используйте синтетические данные; внешние платёжные и Telegram-запросы в тестах подменяются.
3. Выполните проверки своего компонента и общие проверки сайта.
4. Откройте Pull Request с результатом, способом проверки и порядком отката.

```sh
npm ci
npm run test:deals
npm run test:payments
npm run test:reliability
npm run lint
npm run build
python3 -m unittest discover -s services/memora-wallet-manager/tests -v
```

Wallet-тесты используют стандартную библиотеку Python. У Pomodoro отдельная сборка; зависимости, типы и web/desktop-пакеты описаны в [operations](docs/operations.md#pomodoro-builds). Согласуйте доступ к исходным сценам и ключу сборки до изменения их формата.

## Данные и развёртывание

Конфигурационные примеры должны содержать пустые значения или очевидные заглушки. Файлы `.env`, рабочие базы, резервные копии и пользовательские журналы остаются вне Git. Перед публикацией проверьте diff, историю коммитов и прикладываемые файлы.

Слияние в `master` запускает production workflows. Перед merge проверьте CI, влияние на данные, совместимость хранилища и доступную точку восстановления. Сейчас сборщики публичных туристических данных ещё пишут прямо в `master`; перевод их публикации в отдельный поток и обязательные CI-проверки ветки остаются отдельным этапом.

## Лицензирование

Общая лицензия проекта ожидает решения владельца; в Pomodoro есть противоречащие друг другу условия. Публичный доступ к исходникам сам по себе не предоставляет лицензию на произвольное переиспользование. Условия передачи и использования сторонних изменений согласуются до их принятия.
