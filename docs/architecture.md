# Карта проекта для разработчика и аудитора

Memora объединяет несколько продуктов в одном репозитории. Эта карта описывает
текущие границы компонентов, способы проверки и известные ограничения.

Точки входа, команды и способы выпуска сведены в
[каталоге компонентов](component-map.md). Воспроизводимые показатели загрузки и
границы их интерпретации записаны в [baseline производительности](performance-baseline.md).

## Компоненты и данные

| Компонент | Исполнение | Хранилище и внешние зависимости |
| --- | --- | --- |
| Публичный сайт, лаборатория, страницы продуктов | React/Vite в браузере, ленивые страницы | Статика; API Node.js для серверных функций |
| Pomodoro web | Общий renderer + [api-web.ts](../memora-pomodoro/src/web/api-web.ts) | Настройки и история в localStorage текущего origin; таймер во вкладке |
| Pomodoro desktop | Тот же renderer, Electron main/preload | Локальная SQLite через SQL.js; таймер и системные интеграции в main |
| Управление, Kanban, Travel Radar | [server.js](../server.js), модули [server](../server/) | PostgreSQL, YooKassa и Telegram при явной настройке |
| Wallet Manager | Отдельный Python-процесс | Отдельное рабочее хранилище; [инструкция](../services/memora-wallet-manager/README.md) |
| BDayBot | Отдельный сервис | Здесь находится интеграция панели; полный бот расположен в другом репозитории |

Сайт и web-таймер используют разные версии React и изолированы iframe. Это
позволяет переиспользовать desktop-интерфейс без объединения двух React runtime.
Выбранный источник статических файлов передаётся в iframe; документ и localStorage
сохраняют origin сайта. API-запросы и пользовательские данные остаются на сервере
Memora и в хранилищах соответствующего продукта.

## Загрузка интерфейса

HTML → выбор источника → параллельная загрузка CSS и статических модулей → запуск
React после CSS → загрузка нужной страницы по маршруту.

[browserBoot.js](../build/browserBoot.js) выбирает GitHub Pages, jsDelivr или
origin. Каждый запуск ограничен по времени. При сбое создаётся новый документ:
это исключает запуск двух React-приложений из запоздавших динамических импортов.
[entryModules.js](../build/entryModules.js) включает в предварительную загрузку
только статические импорты; остальные страницы остаются ленивыми.

Относительные адреса ресурсов Pomodoro сохраняют выбранный CDN и его префикс.
[Проверка web-сборки](../scripts/check-pomodoro-assets.mjs) проверяет пути шрифтов
и импортированных изображений после каждой сборки. Для реализации используются
[relative base Vite](https://vite.dev/guide/build#relative-base) и
[modulepreload](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/modulepreload).

CDN — внешняя граница доверия для исполняемого кода. Сейчас проверяются точный SHA
релиза, успешные workflows и наличие файлов; отдельная проверка SRI каждого
динамического модуля отсутствует. Доступы к GitHub, Actions и публикации CDN
относятся к критическим доступам проекта.

## Сервер и платёжная граница

Публичные и административные маршруты разделены проверками в HTTP-сервере.
Управление использует Basic Auth поверх HTTPS. Внутренние ошибки, лимиты тела,
проверки webhook и авторизацию следует проверять по конкретным маршрутам.

Запрос платежа сначала фиксируется в PostgreSQL вместе с неизменяемым телом и
ключом идемпотентности. Затем захватывается временное право отправки и выполняется
POST. Webhook проверяется авторизованным GET к провайдеру; идентификатор/nonce,
сумма, валюта и подписка должны совпасть. Фоновая сверка восстанавливает потерянные
ответы с тем же ключом в ограниченном окне. Неопределённые поздние результаты
требуют ручной проверки. Детали и откат: [operations](operations.md#payment-delivery-and-recovery).

Хранилище платежей сейчас использует JSONB-записи с блокировкой и ограниченной
историей. Это проверенная текущими тестами реализация; отдельные таблицы событий,
нагрузочные пределы и долговременный бухгалтерский журнал требуют дальнейшей работы.

## Выпуск и восстановление

PR → CI → merge в master → сборка ресурсов для точного SHA → проверка SHA на VPS →
подготовка отдельного приложения → переключение → `/health` → сохранение релиза.

Сбой переключения восстанавливает предыдущее приложение, зависимости и настройки.
Журнал незавершённого переключения переживает перезапуск updater. Рабочая база
сохраняется: откат кода не восстанавливает старую копию платёжных данных.
[Тесты выпуска](../deploy/vps/test-memora-update.sh) используют изолированные
каталоги и подмены сервисов. Инструкция: [verified releases](operations.md#verified-vps-releases).

## Как провести собственную проверку

1. Зафиксируйте commit SHA и выполните команды из [README](../README.md).
2. Соберите публичные web/desktop-версии Pomodoro без ключей сервисов.
3. Запустите reliability-тесты: внешние платежи, Telegram и база подменяются.
4. Воспроизведите ошибку в своём окружении с синтетическими данными.
5. Передайте обычную ошибку через Issue, уязвимость — по [SECURITY](../SECURITY.md).

Публичный режим заменяет художественную сцену Ninja процедурной «Орбитой». Он
позволяет проверить общий код приложения; побайтовая воспроизводимость официального
установщика этим режимом не заявляется. Текущий Windows-установщик
выпускается без цифровой подписи. Права на использование кода и графики описаны в
[разделе лицензирования](../README.md#публикация-и-лицензия).

## Открытые ограничения

- Внешняя доставка крупных файлов с origin периодически зависает; резервный CDN
  помогает загрузке, локализация сетевой причины продолжается.
- Плавность сцен требует измерений на слабых устройствах и в iframe вне экрана.
- Node.js 20 ещё используется в production/CI; переход на поддерживаемый LTS остаётся задачей.
- Сборщики публичных JSON-данных пишут в master; обязательные проверки перед merge
  требуют отделения этого потока. У updater есть отдельный строгий allowlist данных.
- Резервные копии на том же VPS требуют дополнения offsite-хранилищем и проверкой восстановления.
- Единая лицензия и условия использования художественных ресурсов ожидают решения владельца.

Эта карта и тесты помогают провести аудит. Завершённый независимый аудит безопасности
и гарантии производительности для всех устройств сейчас не заявлены.
