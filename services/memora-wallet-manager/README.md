# Memora Wallet Manager

Telegram-бот для учёта расходов, бюджета, периодических отчётов и ежедневных уведомлений.

## Переменные окружения

- `TELEGRAM_BOT_TOKEN` — токен `@MemoraWallet_bot`;
- `WALLET_DATA_DIR` — каталог постоянных данных, на VPS используется `/var/lib/memora-wallet-manager`.

В production бот работает как отдельный systemd-сервис. Хранилище `user_data.json` проверяет структуру и числовые значения, сохраняет файлы атомарно с `fsync` и оставляет предыдущую корректную версию в `user_data.previous.json`. На Linux писатели используют `flock`; ревизия прочитанного снимка защищает от сохранения поверх более свежей записи.

Ошибка чтения, повреждённый JSON, устаревший снимок или ошибка записи прерывают операцию и доходят до обработчика ошибок бота. Некорректная сумма вызывает ошибку валидации. Маркер `user_data.initialized` сохраняет признак существующего хранилища: исчезновение основного файла после перезапуска требует восстановления оператором. Данные сообщений Telegram исключены из общего журнала ошибок, HTTP-логи с токеном подавлены.

## Проверка

```sh
python3 -m unittest discover -s services/memora-wallet-manager/tests -v
```

Тесты используют временные каталоги и фиктивные данные, без запросов в Telegram.

## Восстановление после повреждения

1. Остановить `memora-wallet-manager.service` и сохранить закрытую копию каталога данных для расследования.
2. Проверить JSON и структуру выбранной копии через `storage.normalize_user_data(json.load(...))`. Сверить дату и полноту истории: `user_data.previous.json` содержит состояние до последней записи; отдельные серверные архивы дают более ранние точки восстановления.
3. Оператор выбирает корректную версию и устанавливает её как `user_data.json`, владелец `memora-wallet:memora-wallet`, права `600`. Маркер и резервную копию сохранить.
4. Запустить сервис, проверить журнал ошибок и стабильность PID/счётчика перезапусков. Восстановление из копии может потерять более поздние изменения; выбор точки восстановления требует проверки.

Это локальная защита JSON-хранилища. Внешние резервные копии и переход на транзакционную БД для нескольких экземпляров бота — отдельные задачи. Изменения профиля, вычисленные обработчиком до `await`, также требуют отдельного контроля конкурентных обновлений при расширении архитектуры.
